# DR-013 元件視覺語言：B1 標本卡

- 狀態：已採納
- 日期：2026-10-07
- 決策者：Czesio

## 背景

公開頁面元件需要一個共同的視覺語言。比較過三個方向，都用同一組真實內容渲染：

- A 延續：把現有系統做完整
- B 標本館：理性為骨
- C 深海：以 Abyss 為主場

選定 B 之後，再細分成四個變體：B1 標本卡、B2 圖版、B3 測繪、B4 深度。

## 決策

採用 **B1 標本卡** 作為所有元件的基礎語言：

1. **細線**：卡片與容器用 1px 的 `border.decorative`，不用陰影區分層次。
2. **2px 圓角**：卡片、按鈕、輸入框一律用 `radius.xs`（2px）。膠囊形只留給 Chip 與 StatusBadge。
3. **Abyss 頂邊**：卡片、Callout、案例等「可被引用的單位」頂邊改成 2px Abyss，像標本卡的標頭。
4. **等寬字的中繼資料**：編號、日期、分類、單位、頁碼一律用 IBM Plex Mono 的 `font.size.sm`，顏色 `text.muted`。
5. **編號標籤**：區塊用 `No. 01`，圖用 `Fig. 01`。編號必須有意義（順序、引用），不能只是裝飾。

B2 的引線標註另外採用，見 [DR-015](DR-015-leader-line-annotation.md)。B 方向原本的脊椎線由耳塞年層取代，見 [DR-014](DR-014-signature-element.md)。

## 理由

- 「精準為先，溫度隨後」：細線、等寬字、編號建立精準感；暖色背景與 Bone 細線提供溫度。
- 標本卡的語言可以延伸到產品介面與文件，不只適合行銷頁。
- 不靠陰影，深色模式之後要補時，結構不必重做。

## 影響

- 所有元件 CSS 依這五條規則撰寫。
- `shadow.*` token 只用於浮層（Drawer、Toast、Select 的選單），不用於卡片。
- `radius.*` 改為 2／4／8／12px 加 pill，刪除 `radius.xl`。舊的 6 至 26px 圓角屬於上一版的柔和風格，不再使用。

## 不採用的選項

- **A 延續**：視覺辨識度不足，和一般 SaaS 範本難以區分。
- **C 深海**：大面積 Abyss 對長文閱讀不友善，也讓中文內文的對比與層次更難處理。
- **B2 圖版、B3 測繪、B4 深度**：B2 的雙框與羅馬數字過於古典；B3 的座標與比例尺在多數內容中沒有意義；B4 把頁面深度寫成「−200 m」，資訊是假的，違反精準原則。
