## 1. 目的

建立 Walking Whale 唯一的設計系統源頭，讓 Claude 與團隊產出中英同等品質的品牌輸出。

v0.1 只建系統本身。官網（`walking-whale` repo）是參考對象，用來萃取已經存在但沒寫進文件的設計決策；官網改版另案處理。

### 3.1 公開頁面元件與模式

形式依 [DR-004](../decisions/DR-004-component-format.md)：CSS class 加 HTML 範例，每個元件附 `.prompt.md`。清單取自官網公開頁面（Home、Articles、Article、Layout）實際用到的元素。

- **頁框**：Topbar（含語言切換）、行動版 Drawer、Footer
- **品牌元素**：Logo、Kicker（改版後規格）、RuleAccent
- **動作**：Button（primary、secondary、ghost、signal）、文字連結
- **內容**：Card、Chip、StatusBadge、PullQuote、Callout（info、warn、danger）、TL;DR、Stat、Table、Code block、Figure 與圖說
- **文章**：文章排版（標題層級、內文、清單、引文、目錄）、文章卡片列表、標籤篩選列
- **表單**：Input、Textarea、Select、Checkbox、Radio、Switch、驗證狀態
- **狀態**：Loading、Empty、Error、Toast
- **頁面模式**：Hero、區塊開頭（Kicker＋標題＋RuleAccent）、服務卡片區、案例列表、團隊區、CTA 區、聯絡區

### 5.1 驗收情境

1. 新開一個 Claude 對話，只提供本 repo，請它產出中英各一頁的服務介紹頁。CI 對比檢查全過，Czesio 審閱時不需要修正任何設計規格。
2. `specimens/index.html` 在 macOS Safari、iOS Safari、Windows Edge 三個環境截圖，確認：
   - 中文標題換行時沒有行距重疊
   - 破折號連續、刪節號置中
   - 中英混排時西文字沒有明顯縮小
3. 官網目前的五個中文問題逐一對照：區塊標籤、標題行距、假斜體、標點字形、翻譯腔。每一項都要能在系統中找到對應的規則。

## 7. 風險與依賴

- **Wordmark 重建**：需要你逐一確認比例與字距，是唯一需要你親自判斷的設計項目，最容易卡住時程。
- **思源宋體在 Windows**：低解析螢幕上細筆畫可能發虛。內文需要實測，必要時 Windows 內文改用思源黑體。
- **舊 skill**：兩個舊 skill 沒更新前，Claude 仍會讀到舊的字體與顏色規格。
- **公開 repo**：本 repo 是 public。任何客戶提供的材料、客戶專案文件、未公開的案例內容都不得進入本 repo；從官網 repo 萃取規格時只帶走設計決策，不帶走內容與資料。
